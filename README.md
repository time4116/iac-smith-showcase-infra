## Local validation and state safety

Run `python3 -m unittest discover -s tests -v` for offline workflow/IAM contracts.
PR CI uses backend-disabled Terraform init/validate, not an AWS plan.
Terragrunt is pinned to v0.57.0 in the apply workflow. The shared root generates
only Terraform backend configuration; it cannot auto-create/update backend
resources during plan/init. Missing state infrastructure must be provisioned by
the explicit approval-gated bootstrap apply job. A failed/cancelled bootstrap
blocks both foundation and workload jobs. A shared `root.hcl` change selects all
consumers, so this PR also selects existing stacks for the gated apply workflow.
No live AWS plan or apply was performed to validate this change. Backend bucket
hardening and environment-bound credential placement remain separate follow-up
work; the existing protected `non-prod` approval gate is preserved.

## Warnings

* No data transformation or validation is configured; raw records will be written to S3
* No dead-letter queue or failed record handling mechanism is specified; records exceeding Firehose limits may be lost
* S3 bucket lifecycle policies are not configured; versioned objects will accumulate indefinitely
* No monitoring or alarms are configured for stream throughput, delivery latency, or failed deliveries
* Firehose does not natively support schema validation; data quality depends on upstream producers
